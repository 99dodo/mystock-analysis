Phase 1 第一階段：基礎建設（只做一次）

1

建 Repo

點右上角頭像 → Your repositories → 右上角綠色 New

捷徑：直接貼網址 github.com/new 也能跳過去，效果一樣。
  • Owner：選 99dodo（就是你自己）
  • Repository name：打 mystock-analysis
  • Description：可打「我的股票分析報告」，不填也行
  • Public / Private：選 Public
為什麼一定要選 Public？
GitHub免費帳號的規則是：GitHub Pages（讓網址能公開瀏覽的功能）只能用在Public repo上。如果選Private，Settings裡的Pages功能會直接無法啟用，除非你付費升級成GitHub Pro/Team才能讓Private repo也開Pages。
選Public的意思是：任何人都能看到你這個repo裡的原始碼跟檔案內容（包括你的分析報告html原始檔），這對股票分析報告來說通常不是問題，因為內容本來就是要公開瀏覽的。

什麼情況才該選Private？如果你以後另外開別的repo，裡面放的是不想被別人看到的東西——例如你的skill寫作邏輯、還沒公開的投資策略草稿、私人筆記——那種用途才選Private，並且要有Pro/Team方案才能同時擁有公開網址。這個mystock-analysis repo因為目的就是要公開分享分析報告，所以固定選Public，不受這個限制影響。
  • 下面三個勾選：Add a README file → 打勾；Add .gitignore → 選 None；Choose a license → 選 None
三個勾選各自是什麼、為什麼這樣選：
  • Add a README file（勾）：README.md是repo首頁自動顯示的說明文件，別人（或你自己半年後回來看）點進repo第一眼看到的就是這個。這次要勾，因為我們就是靠這個檔案列所有分析報告的連結，等於是repo的「目錄頁」。如果不勾，repo會是空的，之後還要手動另外建一個。
  • Add .gitignore（選None）：.gitignore是用來告訴Git「這些檔案類型不要上傳」的清單，通常是給寫程式用的（例如Node.js專案會自動排除node_modules資料夾）。我們這裡只放html報告，沒有程式碼專案，用不到這個功能，所以選None就好。什麼時候該選別的？如果你以後開一個真的在寫程式（例如Python、Node.js）的repo，那時候選對應語言的.gitignore範本，能自動避免把一堆暫存檔、套件資料夾誤傳上去。
  • Choose a license（選None）：授權條款是用來告訴別人「你可以/不可以怎麼使用我這個repo的內容」，通常是給開源軟體專案用的（例如MIT License允許別人自由取用你的程式碼）。我們這是個人股票分析報告，不是要給別人拿去用的軟體專案，選None就好，不代表沒有著作權，只是沒有額外聲明使用授權條款。什麼時候該選？如果你以後想公開一個工具或程式碼，希望明確允許/限制別人怎麼使用，才需要選一個授權條款（例如MIT、Apache 2.0）。

都填完後，按最下面的綠色 Create repository。

https://github.com/99dodo/mystock-analysis你的倉庫

開 GitHub Pages

Phase 2 第二階段：Token 金鑰 ⚠️ 最重要

Token = 你家鑰匙，拿到可改你所有檔案。設定錯會被駭。
3

建 Token

點右上角你的頭像 → Settings → 左側選單最下面 Developer settings → Personal access tokens → Fine-grained tokens → 點右上角綠色的 Generate new token

找不到 Developer settings？它藏在左側選單的最底部，要滑到最下面才看得到。
捷徑：直接貼網址 https://github.com/settings/tokens?type=beta 也能跳過去。
  • Token name：99dodo-mystock-push（讓你以後知道這是幹嘛的）
  • Expiration：選 90 days 就好，到期再重產生，比較安全
  • Description：可不填
4

選倉庫（最重要，不要選全部）

  • Resource owner：選 99dodo
  • Repository access：選 Only select repositories
  • 下面下拉，只勾 mystock-analysis，其他都不要勾
這樣就算 Token 外洩，別人也只能動這一個倉庫，不能動你別的倉庫。
5

選權限（最小權限）

往下滑到 Permissions → Repository permissions，只開這兩個就好，其他都保持 No access：

  • Contents：選 Read and write（才能 push html 上去）
  • Metadata：它會自動變 Read-only，不用理它
6

產生並複製 Token

按最下面的 Generate token，產生後會給你一串 github_pat_xxxxxx，按旁邊的複製圖示複製起來。

注意：這頁關掉就看不到 Token，要馬上複製貼給 Claude 用。

Phase 5 第五階段：收尾

11

Token 怎麼處理

方案 A（最安全）：用完即丟 - 做完馬上回 Token 設定頁按 Delete，下次再建
方案 B（你現在用的）：留 90 天 - 90 天內跑別檔共用，到期自動失效，之後照 Phase 2 步驟重新產生一組即可

🔴 絕對不能做的事

❌ 把 github_pat_... 貼到 Facebook、Line、公開社團
❌ 把 Token 上傳到 GitHub 檔案裡
❌ 設成 No expiration 或 All repositories

不小心貼出去了？馬上到 Token 設定頁按 Delete，刪掉就立刻失效。
